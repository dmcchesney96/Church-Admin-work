# Page-by-page workflow

## Authorization
Proceed on the separate public demo, including source improvements and demo publication. Do not request permission between ordinary demo pages. This does not authorize official CMS/DNS changes, live forms, giving transactions, analytics/database edits or emailing staff.

## Scope
Read the complete saved audit, not only this map. Reconcile the October 27 sitemap capture (119 entries) with the current public sitemap. Inventory core pages, detail/archive pages, real external destinations and retired aliases. Do not bypass private/login-protected content.
Preserve the eight existing pages. Backfill missing review visuals and check consistency, then proceed with the new core queue in scope.json. Continue remaining public sitemap routes after core pages.
Each sitemap route needs a disposition before claiming coverage complete. Distinguish recreated pages, intentionally retained external destinations, pending pages and blockers. Do not treat a single representative page as every event/sermon page being recreated.

## A complete page unit
1. Claim the page in canonical STATE.json and write the exact next action to RESUME.md.
2. Refresh its actual public content and links; save source/date and a genuine current-site screenshot.
3. Generate the proposed visual with imagegen using existing demo screenshots/reference boards. Prepare current/proposed/why comparison with numbered arrows. Keep the genuine screenshot unchanged in its own file; never substitute a generated reconstruction.
4. Save/push the proposed visual and comparison board before coding. Add to /review/ and publish a review-only checkpoint where practical.
5. Build semantic working HTML/CSS/JS matching that visual. Reuse the existing theme; update internal demo links to new counterparts only when they actually exist. Retain verified real external forms and resources.
6. Check desktop/phone layout, links/anchors, controls, labels, keyboard/focus and contrast. Capture the actual implemented result; compare to the proposed visual and repair substantial drift.
7. Source helper push/package -> native version save -> native deployment. Preserve exact returned evidence. Poll only nonterminal deployments.
8. Persist post-deployment state and gallery metadata, then push this recovery state. Only then choose the next page.

## Gallery
Use dist/review/index.html and dist/review/assets/<page-id>/ for before, proposed, annotation-board and after images. Add a small footer review link; keep staff review outside the ordinary visitor flow.
Show page status, relevant reasons, current screenshot, annotated proposal, actual implemented screenshot, demo route and outstanding decisions. Public gallery content must be public-safe. Do not deploy private audit/internal documents under dist.
At graceful stop export the gallery images as a photo pack and/or compiled visual booklet if available. Save these requested exports to Library and return real saved links.

## Fidelity and truthfulness
Preserve the full mission in the homepage hero and Abide/Gather/Connect/Multiply. No pre-visit contact invitation on New Here. Preserve doctrinal substance, established group distinctions, real safeguarding requirements and current actual ministry destinations.
Keep the mockup-matched theme: compact headers; original texture/photography; Metropolis; cyan/navy/white; wave dividers; rounded light-blue panels; pill buttons; recognizable icons; white footer. This specific user direction outranks generic printed-document brand guidance.
Do not invent dates, enrollment/capacity, D-group sizes, ministry formats, response deadlines, staff ownership, resource-sharing rights, care handoffs or confidentiality. Put unresolved questions in the staff review and continue independent pages.
Do not publish internal Drive research, create spiritual scores, manufacture stories or add unstaffed services. No form submissions or donations. Expected usability gains are rationale/hypotheses, not measured outcomes.

## Recovery and limits
Save immediately after source capture, mockup, implementation and deployment. Keep the last working URL. If deploy fails, record the failure and never mark the page published.
At restart reconcile source, native versions and deployment state. Resume a nonterminal deployment or reuse its matching saved version/archive rather than duplicating work. Recover successful deployment evidence if a state write was interrupted.
Do not assume scratch survives. Recover through Sites; refresh expired credentials; never persist tokens.
Keep exact artifacts/paths and next action in the canonical state. Use the validator from the workflow skill. Continue sequentially while resources permit; stop cleanly at a real limit/blocker with a useful handoff.
Do not promise unlimited runtime, hard quota detection, final notification after abrupt exhaustion, automatic restarts, or future runs not requested by Dan.
